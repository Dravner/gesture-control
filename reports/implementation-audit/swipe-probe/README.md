# Временная проверка автомата свайпов

36 сценариев:15/30/60Гц × пропуски0/80/200мс × два направления × сохранённая/неопределённая поза во время движения. До движения подаётся спокойная ладонь, затем линейное перемещение0,3 ширины кадра за0,45с; после1,1с — нейтральное состояние. Позы задаются непосредственно контроллеру. MediaPipe, Vision, реальные картинки, OS и пользовательское намерение здесь не измеряются.

Во всех12 группах с0/80мс пропуска получено по одному событию правильного направления на сценарий, без move/click/scroll. При200мс каждый эпизод отменён — срабатывает предел моста0,15с. Фактический промежуток между видимыми отсчётами зависит от частоты/округления и указан в JSON отдельно от заданной длительности.

В первой версии опыта при60Гц непрерывная ладонь не завершала свайп:2/4 событий вместо4/4 в группе без пропусков. При малом приращении за кадр покой ошибочно обновлял начало движения. Добавлена регрессия и временное окно0,12с; после исправления все группы без длинного пропуска дали4/4. Исходные results/timeline/PNG сохранены как before-rest-window*, текущие — results.json/timeline.csv/swipe-counts.png. Это тест инвариантности автомата, не100% точность на камере.

Запуск: `.venv/bin/python reports/implementation-audit/swipe_probe.py`. JSON содержит SHA256 контроллера; полный финальный исходник зафиксирован в source-snapshot.zip в родительском каталоге после проверок. Модель распознавания может выдавать неверные входные позы и координаты; опыт это не исключает.

# Зависание тестового окна / остановка камеры

Пользовательский сеанс20261008T174207-80c0076e:8255 наблюдений,943 с рукой,380,92с. Получена одна системная команда swipe_right и соответствующий shortcut command+right в собственном окне. Это подтверждение одного полученного события, не качества всех пяти жестов.

В сохранённых отсчётах имеются промежутки0,66/26,93/10,18/1,29/60,76/3,13/0,68с. На одном отсчёте compute достиг10,17с, а возраст полученного GUI кадра11,36с. В конце capture сообщил отказ чтения. Полный анализ — failed-session-analysis.json. Сцена продолжала получать ручные клики. Событий сна/пробуждения в отфильтрованном системном журнале этого интервала не найдено. Причина длинных пауз нативной камеры/Vision не установлена.

Подтверждённые дефекты GUI: прекращение потока не отображалось внутри тестового окна, его чекбокс не синхронизировался с отключением главного ввода. Поэтому окно могло выглядеть замершим с включённым управлением, хотя основной поток уже остановился.

Исправления:

- Тест — обычное окно с родителем, рамкой и кнопкой закрытия; автоматический macOS fullscreen/переход между Spaces убран. Удобство этого режима проверяется повторно пользователем, причинность старых задержек не объявляется доказанной.
- При отсутствии свежего пакета более0,5с ввод отключается, удержание освобождается, устаревший кадр очищается и причина показывается в обоих окнах. После восстановления камера работает в наблюдении, ввод сам не включается. Метаданные отмечают stream_stalls.
- При ошибке worker тестовый чекбокс выключен и заблокирован; внутри сцены видна ошибка. Состояние чекбоксов синхронизируется при освобождении ввода.
- До трёх попыток чтения с короткой паузой помогают перенести одиночные пустые ответы камеры; постоянный отказ остаётся явной ошибкой. Это не timeout для блокирующего нативного read().
- Только во время camera session на macOS удерживается user-initiated activity. Она освобождается при паузе/ошибке/закрытии. [Apple описывает этот механизм](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/power_efficiency_guidelines_osx/PrioritizeWorkAtTheAppLevel.html) для недискреционной работы и защиты от App Nap; не утверждается, что App Nap был причиной прежнего сбоя. Idle system sleep не запрещается, постоянные настройки macOS не меняются.

Регрессии сначала воспроизводили отсутствие родителя/рамки, включённый ввод при потерянных пакетах, несинхронный checkbox при error и отказ при двух кратких failed reads. Проверены освобождение activity и откат неудачного запуска. Полный запуск:263 passed16,83с,exit0. Нативное окно и поток затем проверяются отдельно; их результат не заменяется числом тестов.

Статья не редактируется. Предыдущая сборка256 тестов и её source-snapshot остаются в reports/implementation-audit как исторический результат.

## Найденная утечка Apple Vision и исправление

Повторный сеанс 20261008T181810-c7f71405 дал 7336 кадров за 248,86с; затем камера остановилась. Тестовое окно правильно показало ошибку, отключило свой checkbox и закрылось по кнопке. Последующий перезапуск приводил к длительным задержкам интерфейса. Снятый sample процесса53780 (native-thread-sample.txt) показывает physical footprint58,9G/peak59,0G и главный поток преимущественно в Qt raster painting. Системный журнал (native-camera-errors.log) фиксирует переполнение очереди CMIO. Нельзя утверждать, что каждый старый провал имел одну причину; но утечка текущего backend установлена независимо от камеры.

Минимальное воспроизведение: после уничтожения CGImage/provider у переданного Python bytes оставалась одна лишняя ссылка. Даже gc.collect и autorelease_pool не освобождали её. При RGBA1920×1080 это8294400байт/кадр. Замена на CGDataProviderCreateWithCFData с **Python bytes напрямую** тоже не помогала. Рабочий вариант — NSData.dataWithBytes_length_ (нативная копия), затем CGDataProviderCreateWithCFData(native_data). Это локально воспроизведено на установленном сочетании Python3.14/PyObjC12.2.2, не объявляется дефектом всех версий библиотек.

Регрессия tests/test_apple_vision.py::test_native_conversion_releases_python_pixel_buffer использует настоящий CoreGraphics и подставной синхронный Vision request, без GPU/камеры. До исправления getrefcount даёт3/3/3 вместо2/2/2; после —2/2/2. Полный набор проекта:264 passed16,02с,exit0 (команда QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q tests). Первый общий запуск pytest без указания tests ошибочно собрал тесты из каталогов референсов и завершился ошибками collection; он не считается проверкой проекта.

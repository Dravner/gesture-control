# Настольный интерфейс

Запуск из каталога проекта:

```bash
.venv/bin/python launch.py
.venv/bin/python launch.py --video /полный/путь/clip.mp4
.venv/bin/python launch.py --screenshot reports/gui-interface.png
```

Последняя команда делает снимок настоящих виджетов Qt в режиме offscreen и завершает приложение. Это снимок интерфейса без камеры, а не результат распознавания. Камера запускается только кнопкой «Запустить». При воспроизведении видео системный ввод всегда заблокирован.

По умолчанию выбран профиль «Наведение на экран · пять жестов». Выберите источник и запустите поток. Методы нейросети и персональная библиотека находятся в явно выбранном расширенном профиле. Пока флажок «Включить управление системой» не установлен, распознанные команды попадают только в журнал. Для реального управления macOS нужен доступ Accessibility у приложения, из которого запущен Python. Кнопки «Пауза», «Стоп», смена источника и закрытие окна освобождают удержание мыши и выключают системный ввод. Потеря кадров останавливает поток.

Чтобы добавить собственный жест, введите название, выберите статический или динамический тип и команду. При работающем потоке нажмите «Начать запись»: после трёх секунд подготовки приложение автоматически запишет две секунды статической позы или три секунды движения. В шаблон входят только кадры с обнаруженной рукой. Системный ввод во время записи выключен. Можно завершить раньше; для сохранения нужны минимум пять статических или восемь динамических кадров. Пауза отменяет незавершённую запись. Эти шаблоны персональные; качество следует проверять на новых демонстрациях, а не на записи, использованной для шаблона.

Выберите жест в библиотеке, измените команду и нажмите «Сохранить команду». Клавиши сочетания разделяются запятыми, например `command, shift, s`; произвольные shell-команды не поддерживаются. Пользовательские жесты можно удалить после подтверждения. Встроенные жесты остаются в библиотеке.

Кнопка «Добавить пример выбранного жеста» записывает ещё одну демонстрацию и дополняет существующий шаблон, сохраняя его имя и команду. Порог уверенности и время подтверждения доступны в панели настроек; изменение этих параметров выключает системный ввод.


Каждый запуск потока сохраняет отдельный числовой сеанс в `data/sessions/<UTC-дата>-<идентификатор>/`. При паузе, остановке, конце видео или закрытии окна записываются `frames.npz` и `session.json`: признаки `[T,48]`, монотонные timestamps, присутствие руки, исходные и итоговые предсказания, уверенность, фазы, тип метода, признак записи шаблона, полный журнал команд с состоянием выполнения, источник и сведения о системе. Изображения и видео не сохраняются. Для независимой проверки повторов исключайте строки `recording=True`; записи шаблонов не являются тестовыми демонстрациями. Незавершённый сеанс остаётся в памяти до штатной остановки: принудительное завершение процесса может потерять данные.

Отображение непрерывных команд движения и прокрутки ограничено пятью сообщениями в секунду на тип команды. Выполнение и сохранение событий не ограничиваются. Пороги и выбранный метод сохраняются в `data/ui_settings.json`. При первом запуске используется `method` из `models/selection.json`, если файл корректен; резервный метод — `two_stage`. Явный выбор пользователя сохраняется между перезапусками. Реальный ввод при каждом запуске остаётся выключенным.


## Обучение и независимая проверка, версия 2

Кнопка TRAIN по умолчанию записывает три отдельных примера; перед каждым есть отсчёт 3 с. Верните руку в нейтральное положение между примерами. Статическая поза записывается 2 с, динамическое движение — 3 с. Сохраняется один жест с несколькими примерами, одним именем и одной командой. Низкое покрытие руки, недостаточное движение или неполное соответствие доступных 3D-кадров отклоняют пример с пояснением. Дополнительные 3D-координаты не сдвигаются относительно 48D-признаков; мировая последовательность передаётся в шаблон только при полном соответствии принятых кадров. Отсутствующие мировые координаты отмечаются явно.

Выберите пользовательский жест и нажмите TRIAL: это три новых повтора без добавления шаблонов. Для каждого есть отдельный отсчёт, окно выполнения (2/3 с) и ожидание подтверждения (0,3 с для позы, 0,8 с для движения). Во время ожидания закончите движение и уберите руку. Команды в отсчёте не засчитываются. Итог показывает число подтверждённых совпадений для каждого повтора, качество наблюдений и причины отклонения; отсутствие совпадения не обозначается успешной проверкой. В `session.json` сохраняются ожидаемый идентификатор и реальные интервалы; в NPZ — `task_mode`, `task_expected`, `task_index`, мировые координаты и признаки их наличия. `trial_countdown` исключается из проверки; `trial_grace` входит в окно подтверждения. Обучение и независимые повторы нельзя смешивать при оценке качества.

Проверка временно использует режим «Только свои жесты» и отключает экспериментальную нейросеть. После завершения выбранный режим возвращается, системный ввод остаётся выключенным. Три режима команд и флажок экспериментальной нейросети сохраняются между запусками; флажок по умолчанию выключен. Панель под камерой показывает расстояние, допуск, прогресс и причину решения. Cancel или Pause отменяют текущий протокол; уже сохранённые примеры остаются в библиотеке. Кнопки записи одного примера и дополнения выбранного жеста остаются доступны.


Для статических команд, различающихся направлением кисти (например палец вверх/вниз), включите «Учитывать поворот кисти» и сохраните профиль. По умолчанию собственная форма допускает вращение, поэтому одинаковая анатомическая поза с разным направлением может оказаться неоднозначной. Флажок доступен только для пользовательских статических жестов.

Если очередь последних результатов скрыла краткую потерю руки, runtime передаёт фактический timestamp последнего обнаруженного отсутствия. GUI освобождает удержание и передаёт это наблюдение в контроллер; короткий разрыв сохраняет движение, более долгий завершает эпизод. В сеансе восстановленное наблюдение помечается `replayed_absence=True`; его время сохраняется точно, не приравнивается к следующему видимому кадру.


## Наведение осью пальца на экран

Это приближённая оценка луча по кисти, а не перенос кончика пальца из картинки камеры. Используйте камеру и одну фиксированную посадку. Направляйте прямой указательный палец к экрану; средний, безымянный и мизинец согнуты. Физические размеры и логические границы выбранного дисплея читаются у macOS. FOV 60° — явное предположение, его можно изменить перед новой калибровкой; приложение не измеряет параметры камеры автоматически.

Нажмите «Калибровка · 9 целей». Нажмите Space или «Начать сбор»: после1,2с подготовки автоматически собираются2,2с наблюдений. Направляйте палец к центру цели, можно опереть локоть. Медианная оценка с подавлением выбросов допускает обычное дрожание; крупный дрейф направления/руки отклоняется. Ненадёжные, устаревшие и сильно колеблющиеся наблюдения отклоняются. После девятой цели проверьте результат и нажмите «Сохранить». Отмена и неудачный fit сохраняют прежний файл. Системный ввод во всём мастере выключен и после выхода сам не включается. Изменение камеры, формата кадра, дисплея или FOV требует новой калибровки.

«Проверить наведение · 5 целей» использует отдельные цели и показывает ошибки в логических пикселях. Эти наблюдения не обновляют калибровку. Ошибка fit на девяти обучающих целях и ошибка на пяти независимых целях — разные измерения; ни одно само по себе не доказывает успех реальных кликов.

Пять жестов: один указательный палец — наведение; короткий щипок — клик, удерживаемый — перенос; указательный и средний открыты, остальные согнуты — вертикальная прокрутка; открытая ладонь после спокойной паузы — свайп влево / вправо. При щипке остальные три пальца остаются согнутыми. Для управления системой нужны свежая надёжная рука, совпадающий контекст калибровки и отдельный флажок ввода.

«Проверка пяти жестов» открывает собственное окно с целями, прокруткой и страницами. Ввод включается отдельно в этом окне, выключается при потере фокуса/закрытии. Журнал сохраняет команды контроллера отдельно от полученных окном mousePress, wheel и Command+Left/Right; ручные действия также попадают в журнал и требуют последующего сопоставления. Автоматического утверждения об успешности нет. На macOS сочетание Command описывается в Qt как Ctrl; Meta означает физический Control.

Калибровка хранится в `data/pointing_calibration.json`; независимые цели и события тестового окна — в `data/pointing_trials`. Числовые сеансы дополнительно содержат сырые image/world координаты с масками наличия, геометрические метки, формат кадра и контекст калибровки. Изображения и видео не сохраняются. Обучение и независимая проверка своих жестов доступны в расширенном профиле, временно используют персональное распознавание и по завершении возвращают выбранный профиль при выключенном вводе.

Неудачные и отменённые попытки экранного мастера сохраняются отдельно в `reports/pointing-v3/attempts` с числовыми наблюдениями и причиной. Они не заменяют рабочую калибровку. Если запись отчёта недоступна, ошибка попадает в журнал; отключение управления и закрытие окна всё равно выполняются.

В мастере метка общего классификатора не является условием приёма цели: проверяются направление и качество оси указательного пальца. Нижняя строка показывает конкретную причину отказа, число пригодных кадров и разброс направления (он диагностический; приём использует центральную оценку и проверку дрейфа). При отказе Space сообщите обе строки диагностики; не меняйте FOV случайным образом.

При отказе итогового fit повторный захват выбранной цели сохраняет другие восемь. Это не обходит физические ограничения модели: неудачная калибровка не сохраняется вместо рабочей. Таймер останавливается при отмене/смене контекста; контекст повторно проверяется перед приёмом и Save. После подавления выбросов проверяется свежесть оставшихся лучей.

Размещение новых обучающих целей: x=.18/.5/.82,y=.18/.44/.70. «Поднять цель» меняет положение до сбора, во время сбора заблокировано. Независимые мишени фиксированы. Preview помогает видеть кадрирование. Продолжение неполной серии — явное действие при совпадающем контексте; предыдущие actualcoords сохраняются, старые pending кадры исключаются, resumed_from записывается.
